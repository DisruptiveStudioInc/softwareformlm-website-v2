# Performance recovery — implementation and validation

## What changed

- Removed the three font preloads that downloaded versioned copies in addition to the unversioned CSS fonts. Existing font faces and `font-display: swap` remain.
- Replaced the fixed HTTP hero preload with an HTML responsive preload. The preload and picture share candidate generation and sizes. Spanish `/alter` uses a video and does not preload an unused computer image.
- Added an import map covering local JavaScript modules, so static and dynamic relative imports receive their own asset versions.
- Preserved animated SVG backgrounds on desktop. Host-page picture media queries select generated frozen SVGs on mobile and reduced motion, independent of the embedded SVG viewport. Both variants remain vector assets.
- Preserved automatic English chat startup. GTM starts on first interaction or five seconds after navigation, with its queue initialized immediately. Clarity has one owner, the existing GTM container, as confirmed by five current-revision mobile traces. No GTM-container changes are needed. Very short visits can be missed by delayed tracking. Deferral moves some third-party work beyond initial paint and Lighthouse's initial measurement window; it does not remove that CPU cost from longer visits.
- Removed 44 demonstrably unused sprite symbols (367 → 323; 903,011 → 817,954 uncompressed bytes). The build conservatively scans templates and local content/configuration and preserves transitive symbol references and shared definitions. The full source and legacy PHP sprite endpoint remain.
- Split the shared UI into a 29-symbol sprite (71,249 bytes; 25,833 bytes with local gzip). Home/blog pages no longer request the full service sprite. Service pages retain the complete 323-symbol set. Both artifacts are generated by the same build.
- Generated missing AVIF/WebP variants for the two newer blog covers. Markdown content, authorship skills, translations, routes, and subsequent posts are preserved.
- Made service-type-2 hero content visible without entrance-animation delays and benefit cards visible without JavaScript. GSAP can still progressively enhance the benefits.

Run `python3 performance/extract_reports.py` to regenerate the normalized JSON/CSV and `corrected-analysis.md` from the supplied archives. Raw archives are intentionally not committed. ## Validation environment and limitations

Lighthouse 13.4.1 was installed in a temporary tools directory, not added to production dependencies. All local comparisons use the same Chromium executable, machine, English page, cold browser profiles, and Lighthouse device presets. Runs are sequential, with revision order rotated between repetitions. JSON reports, DevTools network logs, traces, and screenshots are stored in the ignored `performance/runs/` directory.

The local PHP development server does **not** reproduce origin/Cloudflare compression, cache headers, geographic latency, or production routing. Therefore local metrics compare code variants and are **not** production release-gate evidence. The original production PSI settings also differ from these local presets; do not pool the datasets.

Historical previews use `faffd91`, `29ab203`, and `4d4fc18` (the HEAD before recovery). Tracked dependencies come from each revision; missing local runtime configuration uses a symlink. The candidate is compared directly against the unchanged `4d4fc18` preview in a separate interleaved batch.

The first candidate batch under `runs/recovery/` was aborted after screenshot QA caught an invalid SVG media-query token. Exclude that batch. Corrected SVG XML and image decoding have dedicated regression checks. Also exclude `runs/recovery-v2/` and `runs/recovery-final/`: an orphan browser from the interrupted run consumed CPU, and the latter also overlapped a costly CSS comparison. Earlier provisional figures from these batches are superseded. The final comparison is `runs/recovery-clean/`, after restarting previews with no leftover benchmark browsers. The runner now cleans up child processes when interrupted.

## Repeatable checks

```bash
pnpm run build
vendor/bin/phpunit
vendor/bin/phpstan analyse --no-progress --debug --memory-limit=512M
node tests/third-parties.test.cjs
python3 -m unittest discover -s performance -p 'test_*.py'
```

PHPStan `--debug` avoids a parallel-worker socket restriction in sandboxed environments. Its configured scope is the existing blog/router code; PHP syntax and focused helper tests cover the changed rendering helpers.

Browser checks require Playwright and Chromium, supplied through `PLAYWRIGHT_PATH` and `CHROME_PATH`, plus a PHP preview at `TEST_URL` (default `http://127.0.0.1:8085`):

```bash
node tests/browser-performance.cjs
# Optional real-provider test; emits normal page views, never submits a message:
node tests/browser-live-tracking.cjs
```

These checks isolate application behavior by substituting empty external scripts. They cover actual image decoding, a single hero request across viewport/DPR combinations, duplicate fonts, module URL versions, English/Spanish, reduced motion, JavaScript disabled, mobile navigation, sprite references across 47 service routes, representative service sliders, blog/article rendering, and demo-dialog opening/closing. The separate `tests/browser-live-tracking.cjs` check uses real providers: on this machine the chat launcher became visible at 1,292 ms, one click opened its message field, GTM requested once at 5,000 ms, and Clarity loaded once afterward. This is an unthrottled local observation, not a universal latency guarantee. No messages or forms were submitted. Conversion delivery and form submission success remain unverified. Contact page routes are already disabled in this repository; they were not enabled for testing.

Performance comparisons use a separately running preview per revision:

```bash
python3 performance/benchmark.py --lighthouse "$LIGHTHOUSE_CLI" \
  --target current=http://127.0.0.1:8088/en \
  --target recovery=http://127.0.0.1:8085/en \
  --output performance/runs/repeat-day2
```

`CHROME_PATH` selects the common Chromium executable. Default is five runs per device. For single-change diagnosis, use `prepare_variants.py --output /tmp/sfmlm-diagnostics`, serve its four directories, and pass `--device mobile` to the benchmark runner. Diagnostic variants are disposable and must not be deployed.

## Release and rollback

Deploy the complete tracked artifact, including generated still SVGs, sprite, CSS, and responsive image variants. No server-side build, Nginx change, Cloudflare rule, or GTM edit is required. Do not enable HTML caching that can mix languages/cookies.

Production validation remains required: repeat five interleaved measurements per device on a second day with matching production delivery, and verify real chat visibility within five seconds, one-click opening, event delivery, forms, and conversions. Never send test customer messages or submit forms as part of unattended validation.

Release targets remain mobile median LCP ≤3 seconds and TBT ≤200 ms; desktop median LCP ≤1 second and TBT ≤200 ms; every run CLS ≤0.1. The longer-term mobile p75 LCP target is ≤2.5 seconds. Compare matching environments and record p75 separately from field data.

If a feature change repeatedly worsens median LCP or TBT by more than 10%, or breaks functionality, reverse that feature's recovery commit and rerun the same checks. Do not reset to an old tree or discard new blog content. A broader selective round-two reversal against `29ab203` is only warranted if controlled production comparisons still show regression after these targeted fixes.

## Desktop entrance follow-up

A delayed-library browser test reproduced a visible heading becoming hidden when GSAP initialized. Desktop motion now opts into a temporary pre-paint visibility guard for entrance targets. The hero remains visible. GSAP removes the guard and establishes its initial states synchronously, preserving existing easing, timing, and stagger sequences. A four-second startup timeout or loading failure restores static content and prevents late imports from hiding it again. Mobile, reduced motion, and JavaScript-disabled pages do not opt in.

`tests/browser-entrances.cjs` checks all eight reported groups before their triggers and samples opacity through their entrances, plus delayed, failed and timed-out dependency loading, mobile, reduced motion, and no JavaScript. The browser checks and all 14 PHPUnit tests passed. The earlier Lighthouse table predates this follow-up; it has not been remeasured for this change.
